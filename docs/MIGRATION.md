# План миграции

## Что копируется сейчас

- официальный SVG-логотип из `Дизайн-код ТИТАН АВТО` → `assets/brand/titan-auto-logo.svg`;
- значения дизайн-кода → CSS custom properties;
- выявленные поля legacy-приложений → схема базы и формы ядра.

Исходники, готовые сторис/ценники, персональные документы и архивы не копируются автоматически.

## Этапы

1. Развернуть backend и проверить создание/чтение автомобиля.
2. Провести инвентаризацию реальных JSON-экспортов. Примеры не импортировать как рабочие данные.
3. Сделать dry-run importer: нормализация телефона/цен/дат, отчёт о совпадениях и конфликтах.
4. После подтверждения создать автомобили, лиды, контакты, оценки, контрагентов и сделки с сохранением `legacy_id` внутри `payload_json`.
5. Первыми подключить ценники через адаптер; затем сторис, оценку, звонки, документы/фото и калькулятор.

## Политика конфликтов

- Ничего не перезаписывать молча.
- Если у совпавшей машины разные VIN/госномер — создать запись конфликта и остановить импорт этой строки.
- Пустое значение не заменяет заполненное.
- Более новая подтверждённая запись может заменить старую, а изменение обязательно фиксируется в аудите.
- Файлы копируются в Drive только после привязки к `vehicle_id`.

## Перенос на другой аккаунт

1. Сделать копию таблицы и корневой Drive-папки в новом аккаунте.
2. Создать новый Apps Script deployment под новым владельцем.
3. Задать новые Script Properties и новый PIN.
4. Поменять только API URL во frontend.
5. Проверить права и выполнить smoke test. Код и данные не зависят от адреса текущего владельца.
