# TITAN AUTO — архитектура платформы

## Что найдено

Целевой репозиторий `Titan_Auto` был пуст. Исходные рабочие приложения находятся рядом и остаются неизменными.

| Источник | Текущая технология | Важные данные/функции | Целевой модуль | Статус миграции |
|---|---|---|---|---|
| Генератор документов | React + TypeScript + Vite, IndexedDB, DOCX/ZIP | сделки, контрагенты, ПТС/СТС, шаблоны документов | `documents` + `deals` | подключён к общей базе через adapter/iframe |
| Генератор общих сторис | HTML/CSS/JS, Canvas, JSON | фото, характеристики, цена, готовые серии | `stories` | подключён через adapter/iframe |
| Генератор ценников | HTML/CSS/JS, QR, JSON | характеристики, цена, комплектация, PDF/печать | `price-tags` | подключён через adapter/iframe |
| Дизайн-код ТИТАН АВТО | бренд-гайд и логотипы | цвета, шрифты, тон, официальный SVG | общие стили/ассеты | логотип скопирован, токены применены |
| Калькулятор оплаты | HTML/CSS/JS, JSON | сделки, маржа, кредитная комиссия, выплаты, фактические расчёты | `payments` + `analytics` | подключён к продажам через adapter/iframe |
| Лендинг-визитка | статический HTML и медиа | публичное представление компании | `catalog/public` | legacy; позднее объединить с каталогом |
| Навигатор звонка | HTML/JS, JSON | лид, контекст звонка, следующий контакт, встреча, сообщения | `calls` + `leads` | подключён через adapter/iframe |
| Оценка автомобилей | HTML/CSS/JS, IndexedDB, Canvas, печать | акт, диагностика, рынок, вложения, предложения | `valuation` | подключён через adapter/iframe |
| Редактор загрузки фото | единый HTML | кадрирование фото для объявлений | `photos` | подключён через adapter/iframe |
| CRM Notion | документация процесса | дедупликация, календарь, история контактов | миграционный источник | legacy/reference |

В Google Drive обнаружена корневая папка с существующей таблицей `Titan Auto Data`. Таблица содержит один пустой лист `CRM-Sales-Titan Auto`; существующие записи в нём отсутствуют. Ядро не удаляет этот лист: `setupProject()` создаёт рядом нормализованные листы.

## Целевая схема

```text
GitHub Pages (App Shell: внутренний портал + публичный каталог)
                        |
                        v
              TitanAPI (единственный fetch)
                        |
                        v
          Google Apps Script Web App / Router
                        |
             Services + Repository layer
                 /                 \
                v                   v
       Google Sheets            Google Drive
       structured data          binary files
```

Google Sheets и Drive заменяемы: frontend знает только контракт TitanAPI, а бизнес-операции не зависят от API таблиц.

## Границы первой версии

Ядро включает авторизацию, dashboard, автомобили, лиды, контакты, оценки, задачи, продажи, файлы, аудит и публичный каталог. Генераторы ценников и сторис, конструктор документов, полный модуль оценки, редактор фото, навигатор звонка и калькулятор выплат работают внутри App Shell и получают общие данные без повторного ввода. Сторис сохраняет проект, исходные фото и готовые PNG; оценка записывает финансовые показатели, полную карточку, акт и вложения; фоторедактор сохраняет публикационный JPG; навигатор обновляет лид и создаёт неизменяемую запись контакта с договорённостью и следующим действием. Калькулятор получает канонические продажи, рассчитывает вознаграждения по этапам, фактические расчёты, прибыль и командную аналитику. Все результаты связаны с общей базой и Google Drive.

## Правила интеграции legacy

1. Общие поля читаются из `TitanAPI.vehicles.get(vehicleId)`.
2. Специфические поля модуля сохраняются в нормализованных таблицах либо в `payload_json`, пока схема не стабилизирована.
3. Сгенерированный результат загружается через `TitanAPI.files.upload()` и связывается с `vehicle_id`.
4. Рабочий алгоритм генератора не переписывается без отдельной причины.
5. Исходные папки никогда не становятся runtime-зависимостью опубликованного приложения.

## Два уровня продукта

- Внутренний портал: данные продавцов, закупочные цены, контакты, оценки, задачи, аудит и аналитика. Требует сессию.
- Публичный каталог: только опубликованные автомобили и разрешённые поля. Работает по `#/catalog` без сессии.

## Роли внутреннего портала

- `admin`: полный доступ, реквизиты и создание учётных записей сотрудников.
- `director`: весь операционный и финансовый контур, кроме управления доступами.
- `manager`: автомобили, лиды, контакты, оценки, задачи, документы и медиаматериалы; без общих продаж, маржи, выплат и настроек компании.

Каждый сотрудник входит по отдельному PIN. В таблице хранится только хеш с общим секретом проекта, а session token живёт шесть часов. Проверка прав выполняется в Apps Script для каждого запроса; скрытие пунктов меню служит только интерфейсным дополнением.

Публикация автомобиля наружу управляется полем `public_status`; приватные поля никогда не возвращаются публичным endpoint. Отдельно для каждого фото сотрудник включает признак «Для каталога» в разделе «Фото». Только JPG/PNG/WebP с этим признаком получают доступ по ссылке, когда автомобиль опубликован. Прочие снимки остаются внутренними; при снятии авто с публикации доступ к отмеченным фото закрывается. Публичная карточка не получает данные продавца, закупочную цену, внутренние заметки, документы или расчёты. После перехода со старой версии администратор один раз запускает `file.reconcilePhotoAccess`, чтобы закрыть доступ к ранее открытым внутренним снимкам.
